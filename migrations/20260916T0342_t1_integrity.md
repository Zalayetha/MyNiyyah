# T1 Database Integrity Migration

Migration package: `app/20260916T0342_t1_integrity`

## Preflight

Run these checks against a backup or copied production database before applying the migration. The migration intentionally fails rather than deleting or rewriting rows when existing data violates a new constraint.

```sql
SELECT 'orphan sessions' AS issue, count(*) FROM "session" s LEFT JOIN "user" u ON u.id = s."userId" WHERE u.id IS NULL;
SELECT 'orphan accounts' AS issue, count(*) FROM "account" a LEFT JOIN "user" u ON u.id = a."userId" WHERE u.id IS NULL;
SELECT 'orphan prayer logs' AS issue, count(*) FROM "prayerLog" p LEFT JOIN "user" u ON u.id = p."userId" WHERE u.id IS NULL;
SELECT 'orphan journal entries' AS issue, count(*) FROM "journalEntry" j LEFT JOIN "user" u ON u.id = j."userId" WHERE u.id IS NULL;
SELECT 'orphan reflections' AS issue, count(*) FROM "journalPrayerReflection" r LEFT JOIN "journalEntry" j ON j.id = r."journalEntryId" WHERE j.id IS NULL;
SELECT 'orphan attached verses' AS issue, count(*) FROM "journalAttachedVerse" v LEFT JOIN "journalEntry" j ON j.id = v."journalEntryId" WHERE j.id IS NULL;
SELECT 'duplicate nullable segments' AS issue, count(*) FROM (SELECT "journalEntryId", "verseId" FROM "journalAttachedVerse" WHERE "segmentId" IS NULL GROUP BY 1, 2 HAVING count(*) > 1) duplicates;
```

Also audit values covered by the check constraints in `prisma/schema.prisma`. Resolve violations with a reviewed data migration before retrying; do not silently coerce user data.

## Apply

1. Take and verify a restorable PostgreSQL backup.
2. Record row counts for every application table.
3. Run `pnpm contract:emit`.
4. Run `pnpm exec prisma migration check`.
5. Apply with `pnpm exec prisma db migrate --db "$DATABASE_URL"`.
6. Run `pnpm db:verify` and repeat the row-count checks.
7. Run `pnpm db:seed` twice and confirm the second run produces no duplicate reference rows.

## Recovery

This migration is additive and does not delete rows. If application behavior must be rolled back, restore the backup or remove the named check constraints, foreign keys, and normalized unique index from the migration package in a reviewed emergency change. Never cascade-delete journal or prayer data as a rollback shortcut. The `journalPrayerReflection.prayerLogId` relationship uses `ON DELETE SET NULL`, while journal deletion cascades only to reflections and attached verses.
